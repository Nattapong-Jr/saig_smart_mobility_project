# Smart Mobility: แผนที่จุดเสี่ยงและระบบทำนายความเสี่ยงอุบัติเหตุ

โปรเจกต์นี้พัฒนาขึ้นสำหรับ **Smart Mobility** 
เพื่อสมัครเข้าร่วมแล็บ SAIG โดยนำข้อมูล **Multi-Modal** สองชุดมาผสานกันเป็นเว็บแอปพลิเคชัน
เดียว: สถิติอุบัติเหตุทางรถยนต์ทั่วประเทศไทย (สำหรับวิเคราะห์และทำนายความเสี่ยง) และ
คู่มือกฎหมายจราจรไทย (สำหรับตอบคำถามด้วยเทคนิค RAG) เพื่อสร้างประสบการณ์ที่ครบวงจร:
ผู้ใช้ทราบความเสี่ยงของสถานการณ์ แล้วสามารถถามต่อได้ทันทีว่ากฎหมายเกี่ยวข้องว่าอย่างไร

## 🎯 ปัญหาที่ต้องการแก้ไข

อุบัติเหตุบนท้องถนนในไทยเป็นปัญหาสำคัญ แต่ข้อมูลที่หน่วยงานเก็บไว้มักไม่ถูกนำมาใช้
วิเคราะห์เชิงลึกเพื่อหาแนวโน้มหรือจุดเสี่ยง โปรเจกต์นี้จึงนำข้อมูลอุบัติเหตุ 151,778 
เหตุการณ์มาสร้างเป็นเครื่องมือที่ใช้งานได้จริง 2 ส่วนหลัก:

1. **แผนที่ Heatmap จุดเสี่ยง** — วิเคราะห์จากพิกัดจริงของอุบัติเหตุทั้งหมด
2. **ระบบทำนายระดับความเสี่ยง** — ใช้ Machine Learning ทำนายความรุนแรงของอุบัติเหตุ
   จากปัจจัยแวดล้อม (ประเภทยานพาหนะ, สาเหตุ, ลักษณะถนน, เวลา ฯลฯ)
3. **ระบบถาม-ตอบกฎหมายจราจร (RAG)** — นหาและตอบคำถามจากคู่มือกฎหมายจริง 
   พร้อมอ้างอิงเลขหน้าและมาตรา ลดปัญหาคนไม่รู้กฎหมายเพราะเอกสารราชการอ่านยาก

## 🛠️ Techstack

- **Python** — ภาษาหลัก
- **Pandas** — ทำความสะอาดและวิเคราะห์ข้อมูล
- **Scikit-learn** — สร้างโมเดล Random Forest Classifier
- **Streamlit** — สร้างเว็บแอปพลิเคชัน
- **Folium** — สร้างแผนที่ Heatmap แบบ interactive
- **Google Gemini API** — สร้าง embedding (`gemini-embedding-001`) และ generate 
  คำตอบ (`gemini-flash-latest`) สำหรับระบบ RAG
- **pdfplumber** — ดึงข้อความจากไฟล์ PDF คู่มือกฎหมายจราจร

## 📊 กระบวนการทำงาน

### 1. Data Cleaning
- จัดกลุ่มสาเหตุอุบัติเหตุจาก 107 ค่าที่กระจัดกระจาย (มีคำสะกดผิด/เขียนไม่สม่ำเสมอ) 
  เหลือ 12 กลุ่มที่มีความหมายชัดเจน โดยใช้ keyword matching
- แยกคอลัมน์ `road_characteristic` ออกเป็น `road_shape` และ `terrain`
- เติมค่าที่ขาดหายด้วยหมวด "ไม่ระบุ"

### 2. Feature Engineering
- แปลง `time` เป็น cyclical features (`sin`/`cos`) เพื่อให้โมเดลเข้าใจว่า 23:00 น. 
  กับ 00:00 น. เป็นเวลาที่ใกล้กัน
- สร้าง Label ความรุนแรง (`severity_level`) จากคะแนนถ่วงน้ำหนัก 
  `fatalities × 3 + injuries × 1`

### 3. Model Development
ทดลองปรับปรุงโมเดลอย่างเป็นระบบ 5 เวอร์ชัน โดยใช้ **Recall ของกลุ่มความเสี่ยงสูง** 
เป็นตัวชี้วัดหลัก (แทน Accuracy โดยรวม) เนื่องจากสำหรับระบบเตือนภัยความปลอดภัย 
การพลาดเคสรุนแรงอันตรายกว่าการเตือนเกินความจำเป็น

### 4. RAG System (Retrieval-Augmented Generation)

เพื่อให้ระบบไม่ใช่แค่ "ทำนายความเสี่ยง" แต่ตอบคำถามเชิงลึกเรื่องกฎหมายได้ด้วย จึงพัฒนา
ระบบถาม-ตอบจากคู่มือกฎหมายจราจร พ.ศ. 2522 (52 หน้า) โดยมีขั้นตอนดังนี้:

1. **ดึงข้อความจาก PDF** ด้วย `pdfplumber` และทำความสะอาดอักขระที่เสียหายจาก font 
   encoding แบบ Private Use Area
2. **สร้าง Embedding** ทุกหน้าด้วย Gemini (`gemini-embedding-001`) เก็บเป็น vector 
   ขนาด 3072 มิติ
3. **ค้นหา (Retrieval)** ด้วย Cosine Similarity หาหน้าที่เกี่ยวข้องกับคำถามมากที่สุด 
   3 อันดับแรก
4. **สร้างคำตอบ (Generation)** ด้วย Gemini (`gemini-flash-latest`) โดยกำหนด prompt 
   ให้ตอบจากข้อมูลอ้างอิงเท่านั้น ป้องกันการ "เดา" คำตอบที่ไม่มีอยู่จริง (hallucination) 
   ซึ่งสำคัญมากสำหรับข้อมูลด้านกฎหมาย
5. ระบบแสดงเลขหน้าอ้างอิงและเนื้อหาต้นฉบับให้ผู้ใช้ตรวจสอบได้เสมอ เพื่อความโปร่งใส

**ตัวอย่างการทำงาน:** คำถาม "ขับรถเร็วเกินกำหนดมีโทษอย่างไร" ระบบตอบว่ามีโทษปรับ 500 บาท 
พร้อมอ้างอิงมาตรา 67 และ 152 พร้อมระบุว่ามาจากหน้า 39 ของคู่มือ ซึ่งตรวจสอบแล้วว่าถูกต้อง

| เวอร์ชัน | การปรับแต่ง | Accuracy | Recall (กลุ่มเสี่ยงสูง) |
|---|---|---|---|
| v1 | Baseline (feature ครบ) | 49.5% | 0.20 |
| v2 | ตัด feature ที่ไม่มีผล | 51.5% | 0.15 |
| v4 | Cyclical encoding เวลา | 49.8% | 0.19 |
| **v5** | **Cyclical + class_weight balanced** | **51.5%** | **0.37** |

โมเดล v5 ถูกเลือกใช้งานจริง เพราะให้ trade-off ที่เหมาะสมที่สุดสำหรับเป้าหมายด้าน
ความปลอดภัย นอกจากนี้ยังใช้ **Permutation Importance** แทน Gini Importance แบบมาตรฐาน 
เพื่อหลีกเลี่ยง bias ต่อ feature ที่มีค่าไม่ซ้ำเยอะ พบว่า `first_vehicle` (ประเภทยานพาหนะ) 
และ `cause_grouped` (สาเหตุ) เป็นปัจจัยที่มีผลต่อความรุนแรงมากที่สุด

## 💡 Insight สำคัญที่ค้นพบ

- อุบัติเหตุ **71.7%** มีสาเหตุจากการขับเร็วเกินกำหนด
- อุบัติเหตุส่วนใหญ่เกิดบน **"ทางตรง"** ไม่ใช่ทางโค้งอย่างที่มักเข้าใจกัน 
  (สอดคล้องกับสาเหตุหลักคือความเร็ว)
- **17.2%** ของอุบัติเหตุทั้งหมดจัดอยู่ในระดับความรุนแรงสูง

## ⚠️ ข้อจำกัดของโมเดล

โมเดลมีความแม่นยำโดยรวมประมาณ 51% ซึ่งยังไม่สูงมาก เนื่องจากข้อมูลที่มีไม่ครอบคลุม
ปัจจัยสำคัญบางอย่าง (เช่น ความเร็วขณะชนจริง การใช้อุปกรณ์นิรภัย) เว็บแอปจึงแสดง
คำเตือนเรื่องความไม่แน่นอนของผลการทำนายให้ผู้ใช้เห็นชัดเจนเสมอ ไม่นำเสนอเป็นคำทำนาย
ที่แม่นยำสมบูรณ์
สำหรับระบบ RAG ข้อจำกัดหลักคือคุณภาพข้อความที่ดึงจาก PDF ต้นฉบับ ซึ่งมีปัญหา font 
encoding ทำให้บางคำขาดสระ/วรรณยุกต์ไปบางส่วน (เช่น "เป็น" กลายเป็น "เปน") แต่ไม่กระทบ
ความหมายหลักและความแม่นยำของคำตอบเท่าที่ทดสอบมา

## 🚀 วิธีติดตั้งและใช้งาน

```bash
# ติดตั้ง dependencies
pip install pandas scikit-learn streamlit folium streamlit-folium joblib numpy \
            matplotlib pdfplumber google-genai

# ตั้งค่า Google Gemini API Key
export GOOGLE_API_KEY="your_api_key_here"

# รัน data cleaning และ feature engineering (สร้างไฟล์ข้อมูลและโมเดล)
python explore.py
python feature_engineering.py

# เตรียมข้อมูล RAG (ดึง PDF, สร้าง embedding) — รันครั้งเดียวพอ
python rag_explore.py
python rag_build_index.py

# รันเว็บแอป
streamlit run app.py
```
